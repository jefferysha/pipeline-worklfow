# 设计

## 初始假设

- 以 ProjectsView 现有“按需关注排序”的紧凑列表为基础，在列表上方提供低干扰的桌面聚焦工具。
- 检索和状态过滤保持在功能域内的本地派生状态，不新增 API、全局状态或依赖。
- 视觉继续采用安静的操作控制台方向；图标、颜色和动画只表达检索、筛选和结果变化。
- 上述均为待 Explore 验证的初始假设。

## 风险

- 过滤后可能隐藏用户以为仍可见的项目，需要诚实的结果摘要、清除入口和空结果恢复。
- 检索控件可能挤压 1024px 桌面宽度，需要真实浏览器验证四个目标尺寸。
- 动画可能在高频输入时重复触发，必须限制触发条件并遵守 reduced-motion。

## 待验证问题

- 现有项目总览在真实多项目数据下的主要扫描与定位瓶颈是什么？
- 搜索、状态过滤与既有优先排序如何组合，才不会改变健康状态语义？
- 哪种键盘模型和 focus 恢复能在不引入复杂度的前提下显著改善桌面效率？
