# ADR：Progress 筛选保留画布上下文但隔离交互

## 背景

Progress 已取代独立 Inbox 成为唯一在制操作面。现有状态页签通过降低不匹配任务卡的透明度保留
Workflow 阶段上下文，但这些卡仍是可聚焦按钮，导致视觉筛选、键盘顺序和无障碍树不一致。

## 决策

继续在画布中保留不匹配卡的位置和弱化视觉，但把它们标记为 `disabled` 与 `aria-hidden=true`。
状态页签采用 roving tabindex 与 Arrow/Home/End 键盘模型，并在非 `all` 筛选时显示 polite 状态摘要。
分类仍只消费现有 `deckMatch`，不增加第二套业务判定。

## 备选方案

- 完全移除不匹配卡：拒绝，因为会破坏 Workflow 阶段上下文和卡片位置稳定性。
- 恢复独立 Inbox/决策列表：拒绝，因为会回退已完成的 IA 收敛并重复操作面。
- 只加 `tabIndex=-1`：拒绝，因为鼠标仍可打开视觉上已过滤的任务，语义仍不一致。

## 后果

- 好处：筛选后的可交互集合对鼠标、键盘和读屏一致；现有画布结构与 API 零变化。
- 代价：视觉上仍能看到不匹配任务，必须通过摘要解释它们只作为上下文。
- 验证：组件测试锁定禁用/隐藏/不触发、页签键盘循环、摘要 i18n；真实桌面浏览器检查四宽度、
  主题、状态与 reduced-motion。
