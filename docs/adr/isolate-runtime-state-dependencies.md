# 架构决策记录

## 背景

Dashboard 与项目注册表迁移都需要消费 Tenon 的机器级产品路径。现有实现允许应用层仅传 `homeDir`
后继续隐式读取进程环境，导致显式测试目录被共享运行目录覆盖；生产 Dashboard 还会重复解析路径。

## 决策

产品路径只在进程装配边界解释一次，并以不可变 `ServerPaths` 值对象注入 Server。迁移应用服务必须
显式接收环境映射。kernel 保留所有平台和环境变量解释权，应用层不得重建该规则。

## 备选方案

- 改变 `homeDir` 与环境变量的优先级：拒绝，因为会破坏安装和运行时覆盖契约。
- 只调整 CI 或串行执行测试：拒绝，因为不会修复状态所有权。
- 只修改测试夹具：拒绝，因为生产双重解析仍然存在。

## 后果

- 每个 Server 的全部机器状态路径来自同一解析快照。
- 测试和迁移调用方必须明确表达环境依赖，跨平台执行结果一致。
- 现有 HTTP、CLI、端口、环境变量和文件格式保持兼容。
- 新的应用入口若需要产品路径，必须从装配层接收值对象，不能自行读取进程环境。
