# ADR：Host Plan 使用紧凑目录与已选详情分层

## 背景

Host Plan 的 12 个宿主卡片重复展示 capability，导致四个目标电脑端视口只能同时看到 4–5 个目标。右侧详情只有在选择宿主后才承载决策信息，目录与详情的职责边界不够清楚。

## 决策

1. 保留 master-detail 与 `host-target-plan/v1`。
2. 目录只展示候选识别字段：名称、CLI flag、kind、scope 和选择状态。
3. 把 capability chips 移到已选宿主的 operation panel，在选择操作前完整显示。
4. 保持 catalog 顺序、请求取消、错误映射、复制和只读语义不变。
5. 不新增搜索/筛选状态、依赖、全局 token 或 GSAP 动画。

## 备选方案

- 搜索/过滤：对 12 项目录收益不足，且增加状态与 i18n 重叠。
- 多列卡片：在 1024px master-detail 中宽度不足，会破坏稳定阅读顺序。
- 仅缩小字体/间距：无法解决重复 capability 造成的结构性高度。

## 后果

- 宿主扫描密度提高，当前选择的决策上下文集中到详情区。
- 用户需要先进行一次零副作用选择才能看到完整 capabilities。
- 若宿主数量未来显著增加，筛选应作为独立能力另行设计。
- 组件和 API 分层不变，不产生迁移、兼容或回滚成本；回滚只需恢复 Host Plan 组件布局。
