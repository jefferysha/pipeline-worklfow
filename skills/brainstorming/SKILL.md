# Brainstorming

Turn an ambiguous request into an agreed problem statement before design or code.

1. Read the active change's proposal, design, tasks, and project rules.
2. State the user outcome, constraints, non-goals, and unknowns in plain language.
3. Offer 2–3 materially different approaches when a decision exists; include trade-offs.
4. Ask only questions whose answers change scope, architecture, or acceptance criteria.
5. Record agreed decisions in the change's Superpower design document; do not implement while
   discovery remains unresolved.

Use a compact diagram or comparison table when it clarifies a dependency or state transition.
